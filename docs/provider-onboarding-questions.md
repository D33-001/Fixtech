# Fixtech — คำถามสำหรับเปิดบัญชีทดสอบและทำสัญญา

**ใช้โดยผู้รับผิดชอบโครงการ:** เอกสารนี้เป็นร่างคำถาม ยังไม่ได้ส่งหาผู้ให้บริการ. ห้ามส่ง API key, ข้อมูลบัตร หรือเอกสารตัวตนช่างในแชต/อีเมลทั่วไป.

## ข้อมูลที่ Fixtech ต้องตัดสินก่อนสมัคร

1. ชื่อและรูปแบบผู้ประกอบการที่รับเงินกับ gateway; บุคคล/นิติบุคคลใดออกใบเสร็จและรับผิดชอบการคืนเงิน.
2. กรณีลูกค้าจ่ายผ่านแพลตฟอร์ม เงินเข้าบัญชีใคร, ช่างได้รับเงินเมื่อใด, ค่าบริการ Fixtech หักจากฝ่ายใด, ใครจัดการ chargeback.
3. ลูกค้าบริษัทต้องชำระผ่านแพลตฟอร์ม; ลูกค้าทั่วไปเลือกชำระตรงกับช่างได้. เงื่อนไขทั้งสองแบบต้องปรากฏในสัญญาและ UI.

## Opn/Omise — ผู้ให้บริการรับชำระ

แจ้งเพียงภาพรวมธุรกิจ: เว็บจับคู่ลูกค้าและช่างซ่อมคอม/อุปกรณ์ในกรุงเทพ มี B2C/B2B และต้องการทดสอบการชำระผ่าน gateway. ขอคำตอบเป็นลายลักษณ์อักษร:

- บัญชีประเภทใดรองรับการรับเงินจากลูกค้าแล้วจ่ายช่าง/ทีมช่างภายหลัง? กรณีนี้ใครเป็น merchant of record? มีบริการ split settlement หรือ recipient/transfer ตามสัญญาหรือไม่?
- ต้องใช้เอกสารนิติบุคคล ใบอนุญาตหรือเงื่อนไขเพิ่มเติมใด? หากยังเป็นโครงการนักศึกษา ขอ test mode ก่อนตั้งนิติบุคคลได้หรือไม่?
- ช่องทางเริ่มต้นสำหรับไทยที่รองรับ test mode และราคา 100–3,000 บาทคืออะไร? อัตราค่าธรรมเนียม/ขั้นต่ำ/ภาษี/เวลา settlement ปัจจุบันเป็นเท่าใด?
- วิธีตรวจความถูกต้องของ webhook สำหรับบัญชีนี้คืออะไร? ต้อง fetch charge/event กลับด้วย API อย่างไร และมี idempotency key หรือ metadata สำหรับป้องกัน charge ซ้ำหรือไม่?
- Refund, partial refund, chargeback, รายงาน reconciliation และกรณีจ่ายช่างไปแล้วแต่ต้องคืนเงินมีขั้นตอน/ข้อจำกัดอย่างไร?
- ขอ test key ผ่านแดชบอร์ดของบัญชีโดยตรง; อย่าส่ง key ในคำตอบอีเมล. ขอ sandbox test cases ที่ครอบคลุม success/failure/duplicate/out-of-order.

## iApp — การตรวจตัวตนช่าง

- ขอ sandbox/เอกสาร API สำหรับ OCR บัตรไทย, เปรียบเทียบใบหน้า, active liveness และสถานะงานตรวจ. ผลลัพธ์ใดเท่ากับ “ผ่าน” ตามขอบเขตบริการ และผลใดเป็นเพียงคะแนนที่ต้องให้ Admin พิจารณา?
- ตรวจเอกสารกับฐานรัฐหรือไม่? รองรับช่างต่างชาติและทีมช่างนิติบุคคลอย่างไร?
- ผลตรวจมี reference และวันหมดอายุที่ดึงซ้ำได้หรือไม่? กรณีข้อมูลไม่ตรง, vendor ล่ม, ผู้สมัครอุทธรณ์ หรือข้อมูลเปลี่ยนต้องจัดการอย่างไร?
- Vendor เก็บบัตร/ภาพใบหน้านานเท่าใด, จัดเก็บที่ใด, ส่งต่อให้ใคร, มีสัญญาประมวลผลข้อมูลส่วนบุคคลและวิธีลบ/ขอข้อมูลอย่างไร?
- ราคา sandbox/live ต่อการตรวจหนึ่งครั้ง, ขั้นต่ำ และ SLA ปัจจุบันคืออะไร?

## ข้อมูลราคาและสิทธิ์ใช้

- ช่างแต่ละรายต้องยอมให้ Fixtech แสดง rate card โดยระบุหมวดบริการ รูปแบบ เขต ขอบเขตงาน ยอดรวม/ไม่รวมอะไหล่ เวลาอัปเดตและเวลาหมดอายุ.
- ขอสิทธิ์ใช้ข้อมูลเพื่อคำนวณ “ราคาเครือข่าย Fixtech”; ระบุการถอนสิทธิ์และผลต่อ snapshot เก่า. ไม่อ้างว่าเป็นราคาตลาดทั้งหมด.
- ถ้าต้องการอ้างข้อมูลของผู้ให้บริการภายนอก ต้องมีสัญญา/API, coverage, ความถี่อัปเดต, SLA และสิทธิ์เก็บ/แสดงราคาก่อนเปิดใช้.

## เมื่อได้รับคำตอบ

บันทึกวันที่ ผู้ติดต่อ เอกสารสัญญา และข้อสรุปในที่เก็บของโครงการที่จำกัดสิทธิ์. ส่งให้ทีมพัฒนาเฉพาะข้อกำหนดทางเทคนิคและข้อมูลทดสอบ. ปรับ [แบบสร้างขั้น 1–7](production-step-1-7-build-spec.md) และ [ผลตรวจความพร้อม](production-readiness-review.md) ตามข้อเท็จจริงก่อนเชื่อมเงินจริง.
