# ผลการตรวจระบบ Fixtech 1.0

เอกสารนี้สรุป “สิ่งที่ตรวจแล้ว” และ “สิ่งที่ยังไม่ได้ตรวจ” โดยไม่ปะปนกับประวัติการแก้ไข เหมาะสำหรับใช้ตัดสินว่าระบบสาธิตพร้อมนำเสนอหรือยัง

## 1. วิธีอ่านคำว่า ผ่าน

- **ผ่านระดับเอกสาร** หมายถึงข้อกำหนด ผังข้อมูล API หน้าจอ และกฎธุรกิจไม่ขัดกัน
- **ผ่านระดับโค้ด** หมายถึงชุดตรวจอัตโนมัติสำเร็จในสภาพแวดล้อมที่ระบุ
- **ผ่านระดับระบบสาธิต** หมายถึงเคยเดิน workflow ด้วยบัญชีตัวอย่างและฐานข้อมูลที่ทิ้งได้
- **ไม่เท่ากับผ่าน production** เพราะยังไม่มีเงินจริง ผู้ใช้จริง ผู้ให้ข้อมูลราคาที่ทำสัญญา security audit หรือการรับรอง WCAG เต็มรูปแบบ

## 2. ผลตรวจฐานข้อมูล

- ติดตั้ง DDL สำเร็จบน PostgreSQL ฐานใหม่ที่ทิ้งได้
- schema หลักมี 26 ตาราง, 215 คอลัมน์, 57 foreign key, 26 primary key, 13 unique constraint, 54 check constraint และ 53 index
- ตรวจ rollback เมื่อคำสั่งล้มเหลวแล้ว
- migration พื้นฐานสำหรับแผน production เพิ่มตารางจาก 26 เป็น 34 ตารางได้ แต่ยังไม่ใช่การเปิดใช้ production
- ฐานทดสอบใช้ข้อมูลสังเคราะห์และถูกแยกจากฐานที่มีข้อมูลสำคัญ

## 3. ผลตรวจอัตโนมัติ

- `npm run check` ตรวจไวยากรณ์ JavaScript ผ่าน
- `python -m unittest tests/check_demo_v18_schema.py` ตรวจความตรงกันของ DDL, DrawDB และ ERD ผ่าน 8/8
- ชุด `npm test` เต็มผ่าน 30/30 เมื่อกำหนดฐาน PostgreSQL integration ที่ทิ้งได้
- หากไม่กำหนด `FIXTECH_TEST_DATABASE_URL` ระบบจะข้ามกรณีที่ต้องใช้ PostgreSQL การเห็นคำว่า test ผ่านจึงต้องอ่านจำนวน `skipped` ด้วย
- regression test ครอบคลุมไฟล์ภาพ/MIME ไม่ถูกต้อง ขนาดเกิน 10 MiB เกินสามไฟล์ การอ่านไฟล์ข้ามบริษัท Draft เปลี่ยนระหว่างรอ AI/ราคา และการกดคำสั่งซ้ำ

## 4. ผลตรวจ workflow สี่บทบาท

### ลูกค้าทั่วไป

ผ่านเส้นทาง ยินยอมใช้ AI → อัปโหลดภาพ private → วิเคราะห์ด้วย Ollama/Gemma → แสดงราคาอ้างอิง → เผยแพร่ → จับคู่อัตโนมัติ → แชต/นัดหมาย → รับงาน → ชำระเงินจำลอง → รีวิว/รับประกัน/ข้อพิพาท

### ลูกค้าบริษัท

ผ่านการกรอกรายละเอียดแบบบริษัท แสดงช่วงราคา รับข้อเสนอจำลองสองรายการ เลือกหนึ่งรายการ และเข้าสู่ขั้นนัดหมาย โดยบัญชีบริษัทอื่นไม่เห็นข้อมูลงาน

### ช่างหรือทีมช่าง

ผ่านการเห็นเฉพาะงานที่ได้รับมอบหมาย แชต ตอบรับนัด เริ่มงาน ส่งงานเสร็จ และเสนอการรับประกัน การเข้าถึงงานของช่างรายอื่นถูกปฏิเสธ

### Admin

ผ่านการดูคิวงาน ตรวจรายการรับประกัน/ข้อพิพาท และบันทึกคำตัดสินพร้อม audit log โดยไม่สามารถข้ามกฎสถานะของงานได้

## 5. ผลตรวจ AI และราคา

- Ollama กับ `gemma3:4b` ผ่าน smoke test สำหรับข้อความ การถามต่อ และการส่งภาพในระดับการเชื่อมต่อและรูปแบบ JSON
- โมเดลเคยให้รายละเอียดภาพคลาดเคลื่อน จึงต้องแสดงผลเป็นคำแนะนำเบื้องต้น ให้ลูกค้ายืนยัน และห้ามอ้างว่าเป็นการวินิจฉัยที่แม่นยำ
- เมื่อปฏิเสธ consent ระบบไม่ส่งข้อความหรือภาพให้ AI และเปิดทางให้เขียนสรุปด้วยตนเอง
- เมื่อ Ollama ใช้งานไม่ได้ งานยังอยู่ใน `DRAFT` และผู้ใช้ลองใหม่หรือใช้ manual fallback ได้
- ราคาใช้ `CURATED_PUBLIC_EXAMPLES` พร้อม URL แหล่งข้อมูลและอายุข้อมูล 30 วัน ไม่ใช่ราคาตลาด real-time หรือใบเสนอราคาจริง
- เมื่อราคาอ้างอิงหมดอายุหรือไม่มีข้อมูลตรงประเภทงาน ระบบคืน `ESTIMATE_UNAVAILABLE` และไม่สร้างตัวเลขขึ้นเอง

## 6. ผลตรวจ UI ขั้นพื้นฐาน

- เดินระบบผ่าน browser ครบ 4 บทบาท
- ตรวจความกว้าง 320, 768 และ 1280 CSS px โดยไม่พบ horizontal overflow
- การกด Tab แสดง focus outline และ browser console ไม่มี error ในเส้นทางที่ตรวจ
- แก้กรณีข้อมูลบัญชีก่อนหน้าค้างตอนเปลี่ยนผู้ใช้, ฟิลด์บริษัทโผล่ให้ลูกค้าทั่วไป และค่ารูปแบบบริการค้างหลัง reset form แล้ว
- การตรวจนี้เป็น responsive/accessibility ขั้นพื้นฐาน ไม่ใช่การรับรอง WCAG เต็มรูปแบบ

## 7. สิ่งที่ยังไม่ผ่านหรือยังอยู่นอกขอบเขต

- payment gateway, การหักเงิน, settlement และ refund จริง
- แหล่งราคาตลาด real-time ที่มีสิทธิ์ใช้งานและความครอบคลุมเพียงพอ
- การสมัครและยืนยันตัวตนช่างกับผู้ให้บริการ KYC จริง
- อีเมล, SMS และวิดีโอจริง
- production deployment, penetration test, dependency audit ที่ยืนยันล่าสุด และ security audit เต็มรูปแบบ
- การประเมินความแม่นยำ/ความปลอดภัย AI ด้วยชุดข้อมูลขนาดใหญ่
- การรับรอง WCAG เต็มรูปแบบและการทดสอบกับผู้ใช้จริง
- การพิสูจน์ว่ามีช่างจริงครอบคลุมทุกเขตกรุงเทพฯ เพราะ seed มีเพียงข้อมูลตัวอย่าง

## 8. ข้อสรุป

ขั้น 1–7 ผ่านสำหรับ **Fixtech ระบบสาธิต 1.0 ในรายวิชา** และใช้เริ่มขั้น 8 ได้ ระบบต้องรันด้วยข้อมูลสังเคราะห์ ฐานที่ทิ้งได้ และ payment simulation เท่านั้น ก่อนนำเสนอ ทีมต้องรันคำสั่งตรวจบนเครื่องที่จะใช้จริงอีกครั้งและบันทึกผลใหม่ตาม [แผนทำงานสามคน](step-8-three-person-work-plan.md)
